## Restart

From the project root, start the read API in one terminal:

```sh
pixi run integration-api
```

In another terminal:

```sh
cd dashboard
pixi run serve
```

This workspace's Pixi executable is installed in the outer project's ignored tool directory. Use that executable if Pixi is absent from PATH. PHP/Node are defined in the dashboard's manifest and installed locally. Composer is installed under its ignored Pixi directory. Composer, npm and Pixi lockfiles were generated by their package managers. Composer lock metadata includes dependency authors and email addresses, so that lock remains local under the repository privacy rule; it was not edited by hand.

## Fresh dashboard setup

Run `pixi install` inside the dashboard. Copy `env.example` to `.env`, install Composer locally using its [official verified installer](https://getcomposer.org/download/), and run:

```sh
pixi run php .pixi/composer.phar install --no-interaction --prefer-dist
pixi run php artisan key:generate
pixi run php artisan migrate --seed
npm ci
pixi run build
```

Set `DATA_ENGINE_URL=http://127.0.0.1:8002`. The first build downloads configured fonts; subsequent page loads serve the bundled assets locally. The default Laravel SQLite database is separate from the engine database. Environment, database, sessions and installed dependencies stay ignored.

Do not reseed an existing demonstration database after recording decisions: the shipment seeder replaces the synthetic shipment history. The initial seeding was completed before any user decisions. Two startup fixes were necessary: lot IDs include external shipment references to prevent same-day collisions, and HTTPS forcing applies only in production.
